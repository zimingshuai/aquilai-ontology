**当前业务挑战：**

**1. 国内家用投影市场见顶，价格战挤压利润。** 行业整体萎缩，竞品（坚果、当贝等）中低端发力，极米靠高端化和出海维持份额，国内基本盘难以再扩张。

**4. 内部运营数字化能力滞后于业务复杂度。** 多品类、多版本、多区域并行，传统以人工经验和 Excel 为主的计划模式，难以支撑 BOM 快速变化与全球供应链协同，成为利润释放与现金流改善的主要瓶颈。

**5. 智能化与软件增值服务仍在爬坡。** 投影从硬件向智能终端转型，AI 画质、推荐、智能客服、鸿蒙生态等尚在投入，尚未形成可规模化的软件收入。

### 整体流程

本次 POC 从 BOM、风险 BOM 或授权信息的变化出发，检查变化影响，重新计算备料需求，并评估可能产生的呆滞风险。

**① 发现变化，确定影响范围**

对比前后版本，识别物料增删、用量调整、生效日期及授权数量等变化，列出受影响的项目、物料、需求和供给。

**② 汇总需求，计算备料缺口**

根据各项目的需求和适用 BOM，汇总电子料需求；结合可用库存、在途供给及已批准的替代关系，计算缺口并形成策备建议。无法按期满足的部分单独提示。

**③ 按供应商整理策备建议**

将策备建议按供应商整理，生成供内部审核的参考清单，列明物料、数量和需求时间。参考清单不等同于采购订单。

**④ 评估呆滞风险，比较处理方案**

根据调整后的需求和供给，识别可能剩余的物料，比较取消、延期、替代消耗或转用等方案，同时检查这些方案是否会造成新的缺料。

此外，**历史呆滞分析作为独立流程开展**：选取已发生的呆滞案例，还原当时需求、BOM 和供给的变化，依据现有证据分析原因，形成预防建议。经确认的建议可以配置为后续检查规则。

## 本体模型设计

本章说明四个场景需要哪些数据、如何处理、怎样计算以及输出什么结果。四个场景共用业务数据，每次运行保存输入版本、规则版本和计算结果，支持追溯和复算。

### 共用数据、对象与计算约定

#### 模型对象与共用数据

<sheet sheet-id="0kUdWN" token="XSDzstfqbhTT2StHbegcIajTnFh"></sheet>

四个场景共用以下模型对象（共用数据明细见上方表格）：

| 对象 | 业务含义 | 主要使用场景 |
|-|-|-|
| 项目 | 机型/产品线，需求和 BOM 的挂载主体 | 全部场景 |
| BOM（标准/风险） | 机型结构清单，含版本、生效日期与用量 | 点检、策备、呆滞 |
| 需求（订单/MPS/预测） | 各项目需要数量与日期，覆盖关系明确 | 全部场景 |
| 物料 | 最小跟踪单位（WiFi、SoC 等），用于汇总与库存跟踪 | 全部场景 |
| 供给（库存/未到货订单） | 可用库存、在途与已确认未收货订单 | 策备、呆滞 |
| 替代与转用关系 | 物料间可替换规则及批准条件 | 策备、呆滞、历史 |
| 策备建议与参考清单 | 按供应商整理的建议量，供内部审核 | 策备 |
| 呆滞风险与处理方案 | 剩余物料的风险量与取消/延期等方案 | 呆滞 |
| 历史案例与预防规则 | 历史还原记录与沉淀的检查规则 | 历史 |

#### 对象间基本关系

基本关联为：

**项目需求 → BOM 展开 → 物料需求 → 供给分配 → 剩余缺口 → 策备建议。**

需求、BOM 或供给变化后，重新计算受影响的结果，并进一步评估剩余物料风险。

#### 统一计算约定

- **时间明确：** 每次运行指定观察时间和评估期间。只使用观察时间已知的信息，再按需求日期选择生效的 BOM 和替代关系。
- **单位一致：** 原始值保留不变，计算使用已确认的单位换算关系。损耗计算方式和取整位置统一配置。
- **方案独立：**事实记录与模拟记录分别保存。主案例、历史案例和补充测试使用独立数据包；取消、延期、模拟采购和售后转用只在所属情景内生效。每次运行保存输入版本、观察时间、规则版本和情景编号，不将其他情景的批准关系或计算结果自动带入。
- **缺失不当作零：**缺少关键数据时，暂停受影响的计算或结论，保留仍有证据支持的事实，并列出待补充信息。被删除证据所支持的推导结果也应标记为不可验证，不能继续作为已确认输入。缺少某项证据不等于整案所有结果都失效。
- **结果可追溯：** 汇总数量能够展开到项目、需求、BOM 行及供给记录。

### 点检变化识别与影响分析

**输入**

前后两个版本的 BOM、风险 BOM、替代关系及相关授权信息。

**处理步骤**

1. 确认比较的项目、BOM 类型、版本和适用范围，标准 BOM 与风险 BOM 分开比较。
2. 按物料层级和行标识匹配前后记录，识别新增、删除和字段变化。
3. 根据变化物料、生效日期和适用范围，查找相关需求、库存、未到货订单及生产节点。
4. 生成影响明细和复核任务，保留判断依据及处理记录。

**核心判断规则**

其中：

**标准用量 = BOM 行用量 ÷ BOM 基准数量**

同一项变化通过多条关系影响同一个业务对象时，合并为一条影响记录，保留多条依据，不重复生成同一复核任务。

**输出**

变化清单、影响明细和复核任务。页面支持查看前后版本、受影响对象、判断依据及处理状态。

**异常处理**

### 电子料需求与策备计算

**输入**

项目需求、适用 BOM、新项目估算、库存、未到货供给、已批准的替代关系和供应商条件。

**处理步骤**

1. 确认订单、生产计划和预测之间的覆盖关系，选取有效版本，避免重复计算需求。
2. 按需要日期适用的BOM展开物料用量，汇总各项目需求。
3. 检查替代关系的项目、批次、有效期、比例和批准上限，确定哪些供给允许用于哪些需求。
4. 按已确定的分配优先级分配供给。本主案例先将6,000颗批准旧料用于Z9，再对剩余需求分配新料。
5. 对剩余缺口检查交期、最小起订量及订购倍数，形成策备建议和供应商参考清单。
6. 单独核对授权覆盖范围，输出待授权数量及参考金额。授权不作为物理供给。

相同需要日期的需求按项目编码排序；合格供给按可用日期、供给编号排序。供给分配结果应稳定、可复算。

**核心计算**

**① 需求去重**

订单、生产计划和预测存在明确覆盖关系时，按确认后的口径选取或冲减。

例如：生产计划 20,000 台已经包含订单 12,000 台，则本次需求为 20,000 台。没有覆盖依据时，不能仅凭来源优先级直接舍弃其中一项。

**② BOM 展开**

对已经统一计量单位的 BOM 行：

**下层物料需求 = 上层需求 × 标准用量 ÷ 有效良率**

多层 BOM 按层展开，再汇总同一物料：

**物料毛需求 = 各项目、各有效 BOM 路径产生的需求之和**

良率只在明确适用的层级计入；没有损耗的层级取 1。同一损耗不能同时通过良率和损耗系数重复计算。替代料不作为额外必需组件重复展开。

新项目按以下方式处理：

同一部分需求不得同时按 BOM 展开和估算重复计入。

**③ 供给分配**

**订单未收货量 = max（订单数量 − 累计有效收货量 − 已取消量 − 已关闭未收余量，0）**

根据状态、可用日期和占用情况，确定可分配数量。订单收货转为库存后，不再按原未收货数量重复计入。

一批供给可以分配给多个需求，但应满足：

**同一方案中，该批供给的累计分配量 ≤ 该批可用数量**

为当前需求预留的供给计入已覆盖量；被其他需求占用的数量不能重复分配。

**④ 缺口与替代**

替代计算先检查方向、适用项目、批次、有效期、可用日期、换算比例和批准上限，再按确定的优先级分配。

本主案例优先使用批准的旧料：

> 替代满足量＝符合批准范围、供给可用量和需求上限的实际分配量  
> 剩余新料需求＝物料毛需求－替代满足量  
> 新料缺口＝max（剩余新料需求－已分配新料供给，0）

因此，Z9的20,000颗需求先由旧料满足6,000颗，剩余新料需求14,000颗；加上Z9S的10,000颗，新料需求共24,000颗。按期可用新料15,000颗，缺口9,000颗。

同一批供给在所有项目和替代路径上的累计分配不得超过其可用数量。页面可以先展示直接供给缺口，但最终结果必须满足上述分配优先级，不能因展示顺序改变结果。

**⑤ 策备与供应商分配**

先按供货资格、交期和配额形成供应商初步分配，再分别检查订购条件。

当供应商分配量大于零，且有订购倍数要求时：

**建议量 = 按订购倍数向上取整〔max（分配量，最小起订量）〕**

最小起订量与订购倍数分别配置。取整产生的额外数量单独展示，并纳入后续风险评估。

数量计算和交期检查分别输出。到货时间晚于需求日期时，不能将该建议视为已经解决当期缺料。

**输出**

物料需求明细、供给分配明细、缺口、策备建议和供应商参考清单。每个数字均可查看来源和计算过程。

**异常处理**

需求覆盖关系、单位换算或替代资格不清时，暂停相关最终建议。晚到供给可以用于后续需求，但当前逾期缺口必须保留。内部批准、供应商参考量和采购订单分别记录，不自动转换为可用供给。

### 呆滞风险与处理方案计算

**输入**

指定观察时间的库存、未到货订单、未来需求、BOM、替代关系、保留要求及允许采取的处理措施。

**处理步骤**

1. 计算不采取措施时的分期供需和剩余量。
2. 识别可能无法消耗的数量，区分现有库存与未到货订单风险。
3. 建立取消、减量、延期、替代消耗或转用等方案。
4. 按每个方案调整后的数据重新计算。
5. 比较剩余风险、行动成本及缺料情况。

**核心计算**

**① 分期供需**

第一期期初量取观察时间的可用库存，后续各期：

**本期期初量 = 上期期末量**

**本期期末量 = 期初量 + 本期有效到货 + 其他有效流入 − 实际满足需求量 − 其他有效流出**

**本期未满足需求 = 本期应满足需求 − 实际满足需求量**

初始库存只计入一次。未满足需求保留为逾期需求，后续结转时不得重复累计。

**② 期末风险量**

**风险量 = max（评估期末剩余量 − 经确认的保留量 − 经证实的期后消耗量，0）**

保留量和期后消耗量不能重复覆盖同一用途，也不能仅凭“以后可能会用”扣减风险。

**③ 方案重新计算**

<sheet sheet-id="T5dulC" token="XSDzstfqbhTT2StHbegcIajTnFh"></sheet>

调整后，使用同一套供需公式重新计算。不得直接用“原风险量减去措施数量”代替完整计算。

延期至评估期间之外的供给，单独展示其后续承诺和风险，不视为已经消失。

**④ 金额与可行性**

**风险金额 = Σ（风险数量 × 对应成本单价）**

预计损失需另行结合回收价值、处置方式和损失假设计算；行动成本单独列示，不能与风险金额混为一项。

先检查方案是否满足供货要求，再比较风险和成本。造成不允许缺料的方案不进入推荐结果；缺少价格或处置依据时，仅比较数量，不强行给出金额排名。

**输出**

风险物料清单、分期供需明细和方案对比表，展示措施前后数量、行动成本、缺料及不可行原因。

**异常处理**

同一批数量不能重复用于多个措施。取消需要有可取消依据，转用需要有实际用途和批准关系。没有确定去向的数量继续保留为待处理风险。

### 历史呆滞还原与原因分析

**输入**

历史呆滞案例，以及对应期间的需求、BOM、采购、库存变动和处置记录。

**处理步骤**

1. 检查案例结果及需求、BOM、库存、采购记录的完整性。
2. 按时间还原变化和执行过程。
3. 根据预先确定的阈值及持续时间，定位风险形成和确认时间。
4. 选择历史决策时点，检查当时是否具备可行的干预条件。
5. 形成原因、证据、信息缺口和预防建议。

**核心计算与判断**

**① 核对历史库存**

**期末库存 = 期初库存 + 有效收货及其他入库 − 实际消耗及其他出库**

出入库记录分类互斥，调拨和处置不得重复计算。核算结果与历史库存记录不一致时，先列为待核对差异，不能直接解释为业务呆滞。

未收货、不可取消的采购承诺单独核算，不混入物理库存。

**② 区分事实还原与历史决策**

还原发生过程时，可以使用后续实际收货、消耗和处置记录。

评估某个历史时点能否采取措施时，只使用当时已知的信息，并检查：

- 当时是否已经有足够证据识别风险；
- 相关订单或安排是否仍可变更；
- 措施是否满足业务约束；
- 是否有足够的执行时间。

**③ 计算干预效果**

在相同评估期间和口径下，对比“不干预”与“采取措施”两种方案：

**模拟可减少风险量 = max（不干预风险量 − 干预后风险量，0）**

后续实际结果用于检验假设，不能倒推为当时已知条件。证据不充分时，不输出确定的可避免数量。

**④ 防止重复归因**

同一批呆滞可能涉及多个原因，相关证据可以同时保留，但分配到主要原因的数量应满足：

**各主要原因对应数量之和 ≤ 案例呆滞总量**

无法确认的部分保留为未归因，不强行凑足总量。

**输出**

历史时间线、数量核对结果、原因及证据、待补充信息和预防规则草案。预防规则经审核并试运行后再启用。

**异常处理**

证据不足时，只输出能够确认的事实及待核实问题，不预设原因、可避免数量或责任归属。

## 设计红线

- 不用今天的 BOM 反推历史；不用相关性冒充因果。
- 差异和数量由明确的输入及规则计算。AI可以解释结果，但不能补造业务事实、批准替代关系或修改计算依据。需求量、可分配供给量、未满足量、采购建议量、未消化风险量分别展示；授权覆盖量另行记录。
- 敞口 ≠ 损失；净暴露金额 ≠ 减值；不声称"避免缺料/呆滞金额"，不外推工时基线为年度收益。
- 供应商参考清单默认不可直接外发；POC 全程只读，不写回 PDM/SAP。
- 未知不是零。缺少证据时，只暂停受影响的计算或结论，保留仍可核实的事实，不沿用失去依据的推导结果。各主要原因对应数量之和不得超过案例呆滞总量，无法确认的部分保留为“未归因”。
- 不自动定责个人/部门；盘点账实差异不得误归因为业务呆滞。
- 降本机会挖掘（场景 4）不纳入本次 POC 范围，不做任何演示承诺。
- 一切演示数字标注"演示数据"。
