# Ontology Forge 使用手册（FDE 版）

> 适用版本：v0.3.9+ ｜ 更新：2026-10-16 ｜ 读者：FDE / 开发人员 / 业务建模协作方

## 一、这是什么

一个和你**用自然语言聊着就把本体设计出来**的插件。你上传业务文档（DDL、数据字典、需求文档、访谈记录都行），它陪你走完整个设计流程，最终交付两样东西：

| 交付物 | 给谁看 | 形态 |
|---|---|---|
| **本体拓扑图**（PNG/SVG） | 人——业务方评审、方案汇报 | 实体/属性/关系一图看懂，零环境依赖 |
| **本体 yaml**（studio-model 格式） | 机器——导入 Aquilair 平台 | 平台校验一次通过的导入格式 |

它**不做**的事：不写生产数据、不绕过人工审核、不替你做业务决定——产出的永远是 draft，每一处"资料里没写"的地方都会列成待确认问题（OQ）等你裁决。

## 二、安装

1. 打开 ZCode → **Plugin Marketplace → Add → Add Plugin Marketplace**
2. 粘贴插件市场目录：`D:\documents\elitesland-workspace\aquilair-ontology\plugins`
3. **Personal → dev-aquilair-ontology → Ontology Forge → Install**
4. 新开会话即可使用（旧会话需要重启会话才加载新版技能）

**图片渲染一次性依赖**（只要拓扑图 PNG 才需要，不出图可跳过）：

```bash
pip install playwright
python -m playwright install chromium
```

## 三、快速上手：三种用法

### 用法 1：手上只有文档（最常见）

```
/onto 我有一份 XX 业务的需求文档和数据字典，帮我建本体
```

插件会引导你给出文件（路径/目录/直接粘贴都行），然后自动摄取归位。**只有 DDL 也能开工**——它会先建骨架并给你缺口报告，缺什么后续补什么。

### 用法 2：资料已在工作区

```
/onto models/xx/modeling-brief/ 已经准备好了，开始建模
```

### 用法 3：对已有本体做增量

```
/onto 基于现有 XX 本体，新增一个 YY 场景，只出差异
```

brief.yaml 里 target_engine 指向既有域时自动走增量模式（复用既有实体，只建差异，出变更集）。

## 四、流程走读：你在哪几步出场

整个流程九步，**有三个人工确认点**，其余插件自动跑：

```text
① 场景圈定（Charter+CQ）──→ ★你确认：场景对不对、要回答的业务问题全不全
② 术语与候选抽取（自动）
③ 设计稿合成 ──────────→ 产出 design-proposal.md（纯表格，无需懂格式）+ 骨架拓扑图
④ ★你逐表确认：实体/关系/规则设计（这是最重要的纠错点，改这里最便宜）
⑤ DSL 生成（机械形式化，自动）
⑥ lint 硬校验（自动，13 条）
⑦ CQ 回验（自动）
⑧ 初版候选本体交付：拓扑图 + yaml
⑨ 导入平台后自检（可选）
```

**关键认知：确认点④是硬关卡**——你没批设计稿，它不会往下生成 DSL。审设计稿时重点看：
- 实体表：每个实体的"一句话职责"是否准确、粒度是否合理
- 关系表：**"关系语义名"列**是否说清了"是什么关系"（订购物料✓ / 仅仅"物料"✗）
- 规则表 + 表下"异常处理段核对栏"（防漏）
- 待确认事项（OQ）：哪些转业务方、哪些你自己能裁

## 五、产物说明（models/<域名>/ 目录）

| 文件 | 是什么 | 给谁 |
|---|---|---|
| `design-proposal.md` | 设计提案（含你的确认记录） | 审阅留档 |
| `model.yaml` | 本体 DSL（唯一 source of truth） | 版本管理进 git |
| `topology.png / .svg` | ★ 拓扑图 | 业务方/汇报 |
| `engine-bundle/studio-model.yaml` | ★ 平台导入格式 | 导入 Aquilair 平台 |
| `business-inquiry.md` | 业务问询单（OQ 汇总） | 直接转发业务方 |
| `charter.md / fact-cards.md` | 场景章程/抽取证据 | 追溯 |
| `modeling-brief/` | 你上传的资料包（归位后） | 追溯 |

## 六、导入平台与自检

1. 平台 → 项目管理 → 新建项目 → 填名称 → **上传 YAML**（选 `engine-bundle/studio-model.yaml`）→ 校验通过 → 创建并进入
2. （推荐）导入后从平台下载该工作区的 SDK（aquilair.py），存为 `models/<域名>/platform-sdk.py`，然后：

```bash
python plugins/ontology-forge/scripts/check_platform_sync.py models/<域名>/model.yaml models/<域名>/platform-sdk.py
```

实体/字段/主键/关系四维比对——**平台侧任何手改当场现形**（实战曾抓到主键被改）。发现差异按你的裁决写回 DSL，保持两边同步。

**注意**：平台目前没有"重新导入"功能——yaml 更新后需删除项目重建（项目 ID 会变）；业务方在平台侧加的动作/函数不受影响（新建项目时它们不会跟过来，需要的话在旧行项目保留或平台侧重加）。

## 七、常见问题

**Q：lint 报错了怎么办？**
A：把报错原文发给插件（贴在对话里），它会修复后重跑。lint 是质量闸——不过不进下一步是设计如此，别要求跳过。

**Q：关系/实体名每次生成会不一样吗？**
A：插件有受控词表（glossary）机制——域定稿后命名固化进 glossary，同域重跑/增量自动复用。**同域更新走增量模式（用法 3），不要从零重跑**。

**Q：图片渲染报 Playwright 错误？**
A：装第二节的一次性依赖；断网环境走本地缓存（插件根 `assets/mermaid.min.js`，与 CDN 同版本）自动降级。

**Q：产物落在了哪个目录？**
A：`models/<域名>/` 相对当前会话工作区。若工作区不是专门的本体仓库，插件会先和你确认产物根目录。

**Q：业务方迟迟不回问询单，能定稿吗？**
A：不能自动清零——OQ 是"资料没说清"的显式记录，要么等回复补齐，要么你在评审时显式标记"接受风险"。

## 八、质量机制（为什么可以信任产出）

- **13 条 lint 硬校验**：命名/主键/关系闭合/表达式方言/规则名唯一/受控词表/关系语义名……全部确定性机器检查
- **CQ 回验**：建模前定义的业务问题清单，建完逐条验证本体能否回答
- **OQ 生命周期**：每个"没说清"都有编号、归类（等引擎/等业务方）、裁决留痕——定稿前清零
- **平台对账**：导入后 SDK 四维比对，零丢失零变形有核验
- **人审唯一权威**：三个确认点 + 终审全在人，插件永不越权
