# agents/ —— 本体实施专家（aquilair-fde）人设与跨宿主接入指南

> `aquilair-fde.md` 是**宿主无关的 agent 人设源文件**：正文（身份/权威边界/标准执行流程/建模边界/脚本规则/八件套）各宿主通用，frontmatter 双宿主共存（见该文件头部注记）。各宿主的接入方式与派发约定见下。

## 一、各宿主接入方式

| 宿主 | 接入方法 | 形态 |
| --- | --- | --- |
| **ZCode** | 插件安装后**自动注册**（插件根 `agents/` 目录被自动发现，无需清单字段与手工拷贝）：主代理经 Agent 工具以 `ontology-forge:aquilair-fde` 类型派发 | 派发形态（subagent） |
| **Claude Code** | 插件安装自动注册；或把 `aquilair-fde.md` 拷至 `~/.claude/agents/` | 派发形态（subagent） |
| **WorkBuddy** | 开放平台上传 zip（`scripts/pack_workbuddy.py` 构建），专家市场召唤 | 对话形态（Expert） |
| **Codex** | 插件市场两条命令装齐；agent 人设按平台 agent 机制挂载 | 视平台能力 |

## 二、两种运行形态的差异（关键）

- **对话形态**（WorkBuddy Expert）：可与用户交互，确认关卡（Charter 点① / 设计稿点② / 变更预览呈审）当场对话确认后继续。
- **派发形态**（ZCode / Claude Code subagent）：一次性任务派发，**无法中途与用户对话**——按人设文件 §二"子代理派发模式"执行：确认关卡到达即停、任务令须含起止步骤、跨关卡续跑只认主代理的确认声明、产物落盘并报告路径。

## 三、主代理派发约定（给派发方的话）

1. **分段派发**：把九步建模流水线按确认点切段——典型三段：①摄取+圈定（出 Charter+CQ 即停）②抽取+设计稿合成（出 design-proposal.md+骨架拓扑即停）③已确认后 DSL+lint+CQ+交付。段与段之间由主代理向用户呈审过卡。
2. **续跑带确认声明**：第③段任务令必须附设计稿确认结论（确认人/日期/修改记录），子代理凭此放行；没带就只做到呈审为止。
3. **验收看产物**：子代理报告的产物路径清单（`models/<domain>/` 下）是验收依据——重跑 `lint_model.py` / `check_cq.py` 复核，不以子代理自述为准。

## 四、人设与技能的分工

人设（本文件所在目录）：身份、权威边界、流程骨架、运行形态——宿主无关，改一处全局生效。行为细则（各技能 SKILL.md + references）：摄取判型、建模流水线、评审 checklist——人设只按技能名引用，不重复其内容；**修改行为细则请改技能，不要在人设里另写一份**（漂移的根源）。
